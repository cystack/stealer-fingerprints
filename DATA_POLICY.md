# Data policy

This repository publishes malware-log **structure**, never observed log content. Its purpose is defensive format identification and family-level threat-intelligence reference.

## Allowed

- Malware family metadata supported by public or curator-reviewed attribution.
- Neutral provisional clusters that make no malware-family attribution claim.
- Structural labels: field keys, stable filenames, malware branding, and non-personal banner markers.
- Examples generated by this repository, explicitly declared `SYNTHETIC`, whose values are placeholders only.

## Prohibited

- Accounts, credentials, cookies, tokens, wallet material, personal identifiers, host identifiers, IP addresses, email addresses, geolocation, timestamps, or source paths.
- Observed log bodies, excerpts, attachments, archives, screenshots, executable malware, or content transformed from victim records.
- Distribution-channel identifiers or collection telemetry from private systems.
- Dynamic filenames containing victim, host, geography, timestamp, or collection identifiers.
- A merely masked or hashed value derived from observed data. Transformation does not make victim-derived material suitable for this repository.

Candidate events are exact-schema allowlisted and privacy-scanned. Unknown properties and privacy-shaped strings fail closed. Automated publication is permitted only for a fingerprint whose parser explicitly opts into public structure export and whose family is already curated here as `known_family` with `high` or `medium` confidence. A new family, provisional/low/unknown classification, metadata mismatch, or rejected event requires human review and is not auto-published. A validator cannot prove absence of sensitive material, so maintainers must also review the pipeline and investigate every rejection.

Benign input belongs in private parser test data, not in this public malware-intelligence catalog.

## Removal

If prohibited data is discovered, stop redistribution, follow [SECURITY.md](SECURITY.md), remove it from the current tree, rotate any exposed secrets, and purge it from Git history and forks where possible. Deleting a file in a later commit is not sufficient.
